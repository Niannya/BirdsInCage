# 决定记录与开放问题

最后整理：2026-10-29。此文件旨在避免 Codex 把假设误当定稿。

## Confirmed / 已确定
- 项目名 BirdsInCage；2D 俯视角恐怖解谜 RPG 风格。
- 现阶段先做一个**可玩切片**，而不是先把全游戏大纲、地图和所有谜题完善。
- 垂直切片从玩家由南侧主入口进入宅邸开始；玩家在中央大厅探索并解谜，成功进入西南侧的客厅后结束。
- 当前切片的可探索空间只包含**大厅与客厅**。餐厅、厨房、起居室等一层其他区域仅用于理解空间关系，不自动纳入切片。
- 宅邸的主要房间分别制作成独立的 Unity Scene，并通过门切换场景；当前切片至少包含独立的大厅场景与客厅场景。
- 门切换时同时传递目标场景名与目标出生点名；每个入口在目标场景中对应独立出生点。Hall 与 Parlor 之间的双向切换及按门出生已经在原型中验证成功。
- 切片谜题的具体内容、线索、反馈与文本留待后续讨论。
- 菲洛梅尔的宅邸原先由她和父母生活；父母限制她外出；主要陪伴是玩偶。
- 宅邸后来被魔法恢复，整体基本保持原样。
- **取消佣人设定**，保持菲洛梅尔的孤独。
- 宅邸规模已从早期讨论的“小型”更正为**中型贵族宅邸**；时代方向为 19 世纪，倾向 19 世纪中后期的欧洲乡间宅邸。
- 当前一层的高层级空间关系以 `References/first_floor_sketch_latest.png` 为概念参考：南侧主入口通向中央大厅，客厅位于大厅西南侧；图中比例、尺寸、门窗和家具位置仍可调整。
- 草图中大厅东侧的黄色弧形结构表示一种类似飘窗、向外凸出的弧形窗体；当前暂称**弧形凸窗**，具体建筑名称和立面形式仍待确定。
- 大厅北侧的主楼梯当前被隐藏、伪装成墙壁；次级楼梯位于厨房右侧的独立小楼梯间；起居室中不设置楼梯。
- 嘲树是魔女的真正核心，不是巨人；核心破坏物品只有一次使用机会，可误用。
- 仪式正确元叙事行动是玩家**退出游戏**；保持在线则失败，关联 Alice 结局。重启与存档清除、感谢信有关。
- 贤者不能直白提示退出游戏；记忆线索承担解释灵魂与玩家关系的职责。
- 当前工程使用 Unity 2022.3.62f2、URP 2D 与旧版 Input Manager。
- 协作方式以帮助用户学习 Unity 为主：用户亲自操作编辑器并编写主要脚本；Codex 在用户要求时解释概念、检查代码或提供分级提示，不默认接管全部脚本实现。

## Tentative / 暂定而非定稿
- 英国乡间住宅可作为建筑参考，但尚未指定必须对应某个国家或严格建筑流派。
- 宅邸整体仍倾向约三层，菲洛梅尔房间位于三楼；第三层是完整楼层、阁楼还是塔楼等仍待确定。
- 当前一层草图是用于讨论房间关系的概念图，不是按比例绘制的最终建筑图。

## Open / 尚未决定
- 宅邸的确切国家/文化参照、具体年代、严格建筑风格、完整楼层结构与最终平面图。
- 一层各房间的准确尺寸、门窗位置、家具种类与摆放；大厅东侧弧形凸窗的准确术语、尺寸、高度及窗体构造也未定义。
- 隐藏主楼梯的原因、隐藏时间、具体机制，以及次级楼梯未来连接的楼层。
- 切片谜题、调查内容、叙事文本、失败反馈与是否允许重试。
- 门切换场景时的过渡演出、跨场景游戏状态保存，以及进入客厅后的具体收束表现。
- 核心谜题的具体提示与错误使用后的反馈。
- 玩家退出/重启时存档的安全实现、重启后演出及关卡重试规则。
- 对话文本、音效、美术表现和资源选择。

# 垂直切片计划

## 已确认目标
先制作一个**可玩垂直切片**，用小范围展示本游戏的探索、氛围、解谜与叙事方式。无需先把宅邸整个布局及全章节脚本定稿。

## 已确认范围
**南侧主入口 → 中央大厅探索与解谜 → 进入西南侧客厅 → 切片结束。**

- 玩家从进入宅邸开始，不需要在当前切片中制作村庄、湖边或森林路段。
- 当前可探索区域只有中央大厅和客厅。
- 大厅与客厅分别制作成独立的 Unity Scene，通过大厅中的客厅门切换到客厅场景；后续宅邸主要房间也采用独立场景。
- 谜题发生在大厅，但谜题内容、线索、反馈和文本以后再讨论。
- 进入客厅即到达切片结束点；进入后的具体演出或结束界面尚未决定。
- 一层其他区域只用于维持空间关系，除非用户明确扩展范围，否则不制作成可探索房间。

一层概念关系参考 [`References/first_floor_sketch_latest.png`](References/first_floor_sketch_latest.png)。图中的尺寸、门窗和家具并非最终定稿。

## 当前技术验证方向
目前已经验证玩家移动、跑步、2D 碰撞、摄像机控制、Hall/Parlor 双向场景切换和按门选择出生点。后续仍可能需要：

1. 大厅灰盒及通往客厅的门；
2. 观察/调查物品与简短文本交互；
3. 根据最终谜题需要实现的道具或条件判定；
4. 谜题成功、失败及进入客厅后的收束反馈；
5. 可运行构建；保存/加载仅在切片确有需要时加入。

当前场景规划：

1. `Hall`：南侧主入口、中央大厅、谜题及通往客厅的门；
2. `Parlor`：玩家从门内侧进入，随后触发切片收束。

当前门会传递目标场景名与目标出生点名，新场景中的玩家会移动到对应入口。场景切换的具体过渡表现和跨场景游戏状态保存方式仍待逐步实现。

## 尚待确认
- 选哪一个最能表现游戏特点的谜题？
- 是否展示主线剧透或只展示较独立的局部经历？
- 大厅和客厅的实际尺寸、门洞、家具及可调查内容是什么？
- 谜题失败后能否重试，进入客厅后如何提示切片完成？
- 门切换时采用何种淡入淡出与加载反馈？
- 是否需要保存/读取，以及目标构建平台和演示时长。

## 协作方式
用户正在学习 Unity，并亲自完成主要编辑器操作和脚本编写。Codex 默认提供概念解释、操作步骤、代码检查和按需提示；除非用户明确要求，不直接代写全部游戏脚本或接管整个实现。

## 建议开发节奏
先调查现有工程 → 做最低限度可玩闭环 → 游戏内测试 → 补充气氛、文本、反馈 → 固定一个可演示版本。每阶段用 Git 提交，不要一次开发整个游戏。
